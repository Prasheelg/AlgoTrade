# Pinned quirks and suspected bugs

The test suite (`tests/`) pins the code's **current** behaviour, including everything below. Items marked
**FIXED** were changed on purpose (plan.md "Change 2"). Their old pinning tests were renamed to assert the new
behaviour. To fix another item, open a change request, change the code, and update the pinning test(s) listed
for it (and regenerate golden files only if the change is meant to move them).

Severity: **High** means it can produce a wrong trade, price or alert. **Medium** means wrong tracking,
reporting or duplicate or noisy alerts. **Low** means cosmetic, or only reachable through an unusual edge case.

Test references are `file::test_name`, relative to `tests/`.

## B. Findings from step 4 (writing the tests)

| # | Quirk / suspected bug | Pinned by | Severity / impact |
|---|---|---|---|
| B1 | **Structural-stop float edge.** A stop "exactly" 0.3 ATR below the entry is rejected because `99.0 - 98.4 = 0.5999999 < 0.6`, so the stop falls back to the 1.5 ATR stop. | `test_scanner_evaluate.py::test_structural_stop_bounds_inclusive[98.4-96.0]` | Low: affects only exact-boundary values, but the stop then becomes much wider (96.0 instead of 98.4), which changes qty. A tolerance (or rounding) would fix it. |
| B2 | **Migration backfills `market='IN'` for any NULL market**, even when the key starts with `US|`. This runs on every connect. | `test_state.py::test_migration_backfills_null_columns_on_every_connect` | Medium: any US row written without a market (by a manual insert, an older build or a partial write) is tracked and displayed as an Indian signal (wrong currency, session and Telegram flag). The key prefix could be used instead. |
| B3 | **FIXED (2026-10-14).** ~~`data.fetch_ohlcv` with a flat (non-MultiIndex) frame gives every symbol in the batch the same data.~~ A flat frame is now accepted only for a 1-ticker batch. For a multi-ticker batch, `log.error` names the first 3 symbols and the whole batch is skipped. | `test_universe_data.py::test_flat_frame_for_multi_ticker_batch_is_skipped_with_error` (renamed from `test_flat_frame_is_used_for_every_symbol`), `::test_flat_frame_accepted_for_single_ticker_batch`, `::test_flat_frame_single_ticker_tz_converted_and_short_dropped`, `::test_flat_frame_skips_only_its_batch` | Was **High**: if yfinance ever returns a flat frame for a multi-ticker batch (a library change, or all but one ticker failing), every symbol gets one symbol's prices. That gives wrong signals, entries and tracking for the whole batch, with no error raised. |
| B4 | **Intraday tracker with no bar left on the signal day**: if the first bar after the signal is already next-day, a PENDING row is CANCELLED and a market row is EXPIRED at that bar's close, with `closed_at` = the **next** day (not the signal day). | `test_tracker.py::test_intraday_first_bar_next_day_without_prev` | Low/Medium: an inconsistent `closed_at`, and the exit price is the next day's close rather than the signal day's close. |
| B5 | **`/api/scan` validation order and the `min_score` 0 fallback.** The timeframe is checked first, then `min_score` against the number of families in the requested strategies, and only then does `scan` reject unknown strategy names. A bogus strategy list therefore gets a "Minimum agreeing votes must be between 1 and 1" error instead of "unknown strategy". `min_score: 0` is falsy and silently becomes `config.MIN_SCORE`. A non-numeric `min_score` raises outside the try block (Flask 500). | `test_web.py::test_scan_400_validation`, `::test_scan_min_score_zero_falls_back_to_config` | Low: misleading error messages and a silent fallback. |
| B6 | **`scanner.scan` calls `get_universe` before it validates its arguments**, so a bad timeframe or strategy still triggers an NSE or Wikipedia download first. | `test_scanner_scan.py::test_scan_fetches_universe_before_validation` | Low: wasted network calls and a slow error path. |
| B7 | **A universe spec from the other market is treated as a literal symbol list** (`NIFTY50` on US gives `["NIFTY50"]`, `SP100` on IN gives `["SP100"]`). | `test_universe_data.py::test_index_names_are_market_specific` | Low: a `.env` typo silently scans one non-existent symbol and finds nothing, with no error. |
| B8 | **Flat pivots**: equal highs or lows all count as swing points (`== rolling max/min`), so a flat stretch yields duplicate pivots at the same index. | `test_indicators_zones.py::test_find_pivots_flat_series_every_full_window_is_pivot`, `::test_find_pivots_single_peak_and_trough` | Low: inflates S/R touch counts on flat data. |
| B9 | **FIXED (2026-10-14).** ~~`run_loop` EOD retry re-sends the header after a failure.~~ A new `header_sent_for` flag (per market, per exchange date) means the header is sent once. A failed EOD scan is retried on later loops without the header, and once it succeeds no further EOD scan runs that date. | `test_main.py::test_eod_failure_retried_without_resending_header` (renamed from `test_eod_failure_is_retried_next_loop`), `::test_eod_failing_twice_then_succeeding_sends_one_header`, `::test_eod_persistent_failure_keeps_retrying_with_one_header`, `::test_eod_header_resent_on_next_date_after_failure`, `::test_eod_header_flags_are_per_market` | Was Medium: Telegram spam (one header every `SCAN_INTERVAL_MIN`) during a persistent outage, such as Yahoo being down. |
| B10 | **`state.update_signal` on an unknown key is a silent no-op.** An unknown column raises `sqlite3.OperationalError`. | `test_state.py::test_update_signal_sets_fields_and_updated_at`, `::test_update_signal_unknown_column_raises` | Low: tracker errors (a wrong key) go unnoticed. ## C. Follow-ups noted while verifying Change 2 (not pinned, not fixed)

| # | Observation | Severity / impact |
|---|---|---|
| C1 | `completed_bars` uses the exchange clock with no allowance for Yahoo's data delay (about 15 min intraday). A bar whose interval has ended can still be missing its last minutes when it is evaluated. The same applies to the EOD scan, which runs at the first loop after the close while Yahoo may still be finalising the daily bar. | Low/Medium: the first (deduplicated) alert can come from a slightly incomplete bar. A grace period (for example, bar end + delay <= now) would fix it. |
| C2 | Only the **last** bar is checked. If Yahoo ever returns an extra live stub row (an odd timestamp after the real in-progress bar), the bar before it is still evaluated. | Low: not seen in the current yfinance output. |
| C3 | The EOD retry (B9) only triggers when `run_scan` **raises**. A Yahoo outage inside `fetch_ohlcv` is logged per batch and returns no data, so the scan "succeeds" with zero signals and is not retried. | Medium: during an outage the EOD scan silently finds nothing. |
| C4 | `header_sent_for` is set even when `telegram_bot.send_message` returns `False` (the send failed without raising), so that day's header is never re-sent. | Low: a missing header, not duplicates. |
| C5 | A daily signal found during the session is keyed on yesterday's bar date, the same key as the previous evening's EOD scan of that bar. The dedupe keeps whichever version was recorded first. | Low: this is the intended dedupe, noted here so it is not mistaken for a bug. |
